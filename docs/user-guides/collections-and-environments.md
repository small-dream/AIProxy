# API 集合与环境变量使用指南

## 功能简介

API 集合（Collections）允许你将常用的 HTTP 请求保存、分组和复用，无需每次重新输入。配合环境变量（Environment Variables），你可以在 Dev / Staging / Prod 等不同环境间快速切换，而无需修改请求本身。

与 Postman 的 Collection 功能对标，AIProxy 的独特优势是**可以直接从抓包流量保存请求到集合**。

## 典型用途

- **接口调试**：将项目常用 API 保存为集合，反复调试
- **多环境切换**：同一组请求在开发、测试、生产环境间一键切换
- **团队协作**：导出集合配置分享给团队成员
- **从抓包复用**：将抓到的请求直接保存到集合，省去手动构造

## 入口位置

1. 打开 AIProxy
2. 在左侧导航栏点击 **Collections**

## 页面结构

Collections 页面采用三栏布局：

- **左栏**：集合/文件夹树 + 底部环境选择器
- **中栏**：当前选中集合内的请求列表
- **右栏**：请求编辑器（URL、Headers、Body）+ 响应预览

## 创建集合与文件夹

### 创建顶级集合

1. 在左栏顶部点击 **新建文件夹** 图标
2. 输入集合名称，如 `User API`
3. 点击 **Add**

### 创建子文件夹

1. 将鼠标悬停在某个集合/文件夹上
2. 点击右侧出现的 **+** 图标
3. 输入文件夹名称
4. 点击 **Add**

文件夹支持无限嵌套，用于组织大规模 API。

## 拖拽整理树结构

文件夹和请求项都支持拖拽，用于重新组织 API 集合。

### 操作方式

1. 在左栏的集合树中，按住一个文件夹或请求项并轻微移动（>4 px）即可开始拖拽
2. 拖动时其他行会显示蓝色提示：
   - 行的上/下边缘出现细蓝线 → 松开会**插入到该位置**（与目标行同级，前/后）
   - 整行高亮蓝色背景 → 松开会**放进这个文件夹**（成为它的子级）
3. 把请求项拖到文件夹中部 → 移动到目标文件夹
4. 把文件夹拖到另一个文件夹中部 → 成为其子级；拖到上/下边缘 → 与之同级

如果拖动悬停在折叠的文件夹中部超过半秒，文件夹会自动展开，方便你深入嵌套结构。

### 限制

- **不能把文件夹移动到它自己的子级中**（防止环），此时不会出现拖拽指示线
- **请求项不能与文件夹同级**（请求项只能位于文件夹内）；拖拽到文件夹的上/下边缘不会有指示线
- 树为空时，新建第一个根文件夹仍需通过左上角的 **+** 按钮

### 失败提示

如果服务端拒绝（例如系统出错或并发冲突），UI 会自动回滚到拖拽前的状态，并在底部弹出提示。

## 保存请求到集合

### 在 Collections 页面新建请求

1. 在中栏顶部点击 **+** 图标
2. 右栏会清空编辑器，进入新建模式
3. 填写 Method、URL、Headers、Body
4. 在顶部输入请求名称（如 `GET 用户详情`）
5. 点击 **Save as New**

### 从抓包流量保存（亮点功能）

1. 打开 **Sessions** 页面
2. 找到想要保存的请求
3. 右键点击该请求 → 选择 **Save to Collection**
4. 在弹窗中选择目标集合
5. 可修改请求名称，点击确认

系统会自动识别请求的方法、URL、Headers 和 Body，并推断合适的 Body 类型（JSON / FormData / URL-encoded）。

## 编辑和发送集合中的请求

1. 在左栏点击集合，中栏会显示该集合下的所有请求
2. 点击某个请求，右栏加载其详情
3. 修改 URL、Headers 或 Body
4. 点击 **Send** 按钮发送请求
5. 响应会显示在右栏下半部分

### 更新已保存的请求

修改后点击 **Update** 按钮，会直接覆盖原请求。如果想保留原请求并另存一份，点击 **Save as New**。

## 环境变量

环境变量让你在不同环境（如开发/测试/生产）间切换时，无需逐个修改请求中的 URL、Token 等值。

### 变量语法

在 URL、Headers、Body 中使用双花括号包裹变量名：

```
https://{{baseUrl}}/api/users
Authorization: Bearer {{token}}
```

### 创建环境

1. 在 Collections 页面左栏底部，点击环境选择器旁的 **齿轮** 图标
2. 在弹出的环境管理窗口中，点击 **New Environment**
3. 输入环境名称，如 `Development`

### 添加变量

1. 在环境管理窗口左侧点击想要编辑的环境
2. 右侧会出现变量编辑表格
3. 点击 **Add Variable** 添加新行
4. 填写 Key 和 Value
5. 修改变量后，系统会在 500ms 后自动保存

| 列 | 说明 |
|---|---|
| 启用开关 | 控制该变量是否生效 |
| Key | 变量名，在请求中用 `{{key}}` 引用 |
| Value | 变量值，发送请求时替换 `{{key}}` |
| 删除 | 删除该变量 |

### 切换环境

1. 在 Collections 页面左栏底部的环境选择器中
2. 选择想要使用的环境
3. 发送请求时会自动使用该环境下的变量值

选择 **No Environment** 表示不使用任何环境变量（全局变量仍然生效）。

### 全局变量

全局变量不绑定任何环境，在所有环境下都生效。

使用场景：
- 存放跨环境通用的值（如 `apiVersion = v1`）
- 作为环境变量的 fallback

**变量优先级**：环境变量 > 全局变量。如果环境和全局都有同名变量，环境变量优先。

### 禁用变量

点击变量行左侧的开关可以禁用该变量。禁用后：
- 该变量不再参与替换
- 请求中对应的 `{{key}}` 保持原样

## 变量替换范围

变量替换会作用于以下位置：

- URL：`https://{{baseUrl}}/api/users`
- Header 值：`Authorization: Bearer {{token}}`
- Header 名称：支持（较少使用）
- Raw Body：`{ "userId": "{{userId}}" }`
- FormData 的字段名和值
- URL-encoded 的字段名和值

未匹配的变量（如环境中未定义 `{{missing}}`）会保持原样，不会报错。

## 环境选择持久化

当前选中的环境会自动保存，下次打开 AIProxy 时会自动恢复上次选择的环境。

## 常见问题

### Q: 为什么发送请求后变量没有被替换？

检查以下几点：

1. 环境选择器是否选中了正确的环境
2. 变量是否已**启用**（左侧开关为打开状态）
3. 变量 Key 是否与请求中使用的 `{{key}}` 完全一致（区分大小写）
4. 如果是全局变量，确认它在"Global Variables"标签页中存在且启用

### Q: 环境和全局变量有同名变量时，哪个生效？

环境变量优先。如果当前环境定义了 `baseUrl`，即使全局变量也有 `baseUrl`，也使用环境变量的值。

### Q: 可以禁用某个环境但保留全局变量吗？

可以。将环境选择器切换到 **No Environment**，此时只有全局变量生效。

### Q: 删除环境会删除其中的变量吗？

会。删除环境时会级联删除该环境下的所有变量，操作不可恢复。

### Q: 变量值支持哪些类型？

当前所有变量值都是字符串类型。数字、布尔值等需要以字符串形式存储（如 `"true"`、`"123"`），请求发送时按字符串替换。

### Q: FormData 和 URL-encoded 中的变量会被替换吗？

会。在 FormData 和 URL-encoded 的字段名和值中都可以使用 `{{variable}}` 语法。

### Q: 可以从抓包保存的请求直接发送吗？

可以。从 Sessions 右键保存到集合的请求，可以在 Collections 页面直接点击发送。系统会自动替换当前激活环境中的变量。
