# AIProxy v0.6.0

## 更新内容

- Agent 新增跨会话的字段搜索：`search_session_fields` 一次调用即可在多个请求或响应体里按 JSON 属性名或 JSONPath 查找，支持"存在"与"按类型的值相等"两种条件。此前只能先列出会话再逐个读取正文，现在不必来回翻页；敏感字段与敏感值不会参与匹配，翻页游标与查询条件绑定，无法跨查询复用。
- 等待流量的可靠性修复：`wait_for_sessions` 的水位线从"插入顺序"改为"完成顺序"。此前一个先建立连接、后完成的慢请求可能永远不会被等待中的 Agent 看到；清空会话后水位线也可能倒退。新水位线按完成事件递增、清空后不回退，并携带数据库标识，换库后旧游标会被明确拒绝而不是静默出错。旧格式水位线仍然可用，Agent 收到提示后按会话 ID 去重即可。
- `wait_for_sessions` 新增 `limit` 参数（默认等于 `minCount`），超时后返回的水位线只覆盖已交付的结果，重试不会跳过尚未返回的匹配。

## What's new

- Cross-session field search: `search_session_fields` scans request or response bodies across sessions in one call, matching an exact JSON key or JSONPath with "exists" or typed scalar "equals". Previously the Agent had to list sessions and read bodies one by one. Sensitive keys and values never participate in matching, and page cursors are bound to the query so they cannot be reused across searches.
- Wait-for-traffic reliability fix: the `wait_for_sessions` watermark now follows completion order instead of insertion order. A slow request that connected earlier but finished after the caller resumed could previously be missed forever, and clearing sessions could move the watermark backwards. The new cursor advances by completion event, never regresses after a clear, and carries a database identity so a stale cursor from another database is rejected explicitly rather than silently misbehaving. Legacy watermarks keep working; the tool tells the Agent to deduplicate by session ID.
- `wait_for_sessions` gains a `limit` parameter (defaults to `minCount`), and the watermark returned after a timeout only covers delivered results, so a retry does not skip matches that were not yet returned.
