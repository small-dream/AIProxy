# AIProxy v0.1.35

## 更新内容

- 规则中心（Rules）四个标签页统一为同一套工作台布局：左侧列表负责选择与拖拽排序，右侧编辑区把「规则名 + 启停」放在顶部身份行，把保存按钮固定在底部操作栏，长表单滚动时保存按钮始终可见，不再需要滚到顶部找按钮。
- 新建规则会自动排到列表末尾。「优先级」输入框收进编辑器的「高级」折叠区：列表顺序本身就是优先级，数字只作为手动微调的备用入口，列表里不再显示优先级数字干扰阅读。
- 规则编辑器新增「复制规则」和键盘快捷键：`Cmd/Ctrl+S` 保存（光标在输入框内也生效）、`Cmd/Ctrl+D` 复制当前规则、`Alt+↑/↓` 上移/下移选中规则、`↑/↓` 在列表中移动焦点；溢出菜单里可查看快捷键说明。
- 断点规则从弹窗表单改为与其他规则一致的内联编辑器，并支持拖拽排序：断点按列表顺序自上而下匹配，第一条命中的规则触发拦截，顺序现在可以直接拖动调整。
- 批量删除（多选后删除）现在会先弹出确认对话框，与单条删除保持一致；此前多选删除会立即执行。
- 修复：搜索过滤生效时拖动（或按 `Alt+↑/↓`）调整顺序，只会重排当前可见的规则，被过滤隐藏的规则可能被挤到错误的位置；现在隐藏规则会保持原有位置。
- 修复：新建规则但未做任何修改时，切换标签页或点选其他规则会被误判为「有未保存的修改」并弹出确认框。
- 规则测试器增强：可从最近捕获的会话中直接挑选样本（自动填充 URL / 方法 / 阶段）；阶段筛选新增「任一」；区分「规则未启用」「不命中」「命中但该阶段永远不会执行」三种结果，不再把不可能生效的规则显示为绿色命中。
- 规则名称等必填字段不再重复标注「（必填）」后缀，只对真正可选的字段标注「（可选）」。

## What's new

- All four Rules tabs now share one workbench layout: pick and drag-sort rules on the left, edit on the right with the rule name and enabled switch pinned in an identity row at the top, and the Save button pinned in a fixed footer, so it stays visible while long forms scroll instead of hiding at the top of the page.
- New rules are appended to the end of the list automatically. The raw Priority number moved into an "Advanced" disclosure: list order is the priority, and the number is only an escape hatch for manual tuning, so the list no longer shows a priority chip that competes with the drag order.
- The rule editor gained "Duplicate rule" and keyboard shortcuts: `Cmd/Ctrl+S` to save (works while a text field has focus), `Cmd/Ctrl+D` to duplicate, `Alt+↑/↓` to move the selected rule up or down, and `↑/↓` to move focus between rows. The shortcuts are listed in the overflow menu.
- Breakpoint rules now use the same inline editor as every other rule domain instead of a modal form, and can be drag-sorted: breakpoints match top-down and the first hit triggers the intercept, so the order is now directly adjustable.
- Batch delete (select rows, then Delete) now asks for confirmation, matching single-rule deletion; it previously deleted immediately.
- Fixed: reordering while a search filter was active only renumbered the visible rules, which could push filtered-out rules to the wrong place. Hidden rules now keep their position.
- Fixed: creating a new rule and leaving it untouched was incorrectly treated as unsaved changes, prompting a discard dialog when switching tabs or selecting another rule.
- Rule tester improvements: pick a sample from recently captured sessions to fill URL, method, and stage automatically; "Either" was added to the stage filter; and the verdict now distinguishes "rule disabled", "no match", and "matches but can never run at this stage" instead of showing an impossible rule as a green match.
- Required fields such as the rule name are no longer suffixed with "(required)"; only genuinely optional fields are marked "(optional)".
