# AIProxy v0.5.0

## 更新内容

- Agent 现在可以从一条已捕获的会话直接创建临时的 JSON 响应改写：`create_session_json_rewrite` 按源请求的协议、主机、路径和查询参数推断出精确的匹配范围，默认只做预览；正式创建的规则在设定时长（60–3600 秒）后自动过期，无需手动清理。
- 新增 `wait_for_session_json_rewrite`：等待真实客户端发出新请求，并用实际捕获的响应验证改写是否生效；回放请求和 AIProxy 自发的受控验证请求不会被当作证据，避免"自己验证自己"。HTTP/2 连接上的响应体改写暂不支持，会在预检阶段明确说明，而不是静默跳过。
- 新增 `extend_session_json_rewrite`：临时的改写规则可以续期，过期后也能重新激活；剩余寿命上限为 1 小时，续期请求支持幂等重试。

## What's new

- The Agent can now create a temporary JSON response rewrite straight from a captured session: `create_session_json_rewrite` infers a precise match scope — scheme, host, path, and query parameters — from the source request and previews by default. A published rule expires automatically after the configured 60–3600 seconds, so no manual cleanup is needed.
- `wait_for_session_json_rewrite` waits for a real client request and verifies the rewrite against the actually captured response. Replayed sessions and controlled verification requests sent by AIProxy itself are excluded as evidence, so the change cannot verify itself. Response-body rewrites over HTTP/2 are not supported yet and are reported clearly at preflight instead of being silently skipped.
- `extend_session_json_rewrite` renews a temporary rule, or reactivates it after expiry. The remaining lifetime is capped at one hour, and renewal requests are idempotent on retry.
