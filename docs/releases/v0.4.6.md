# AIProxy v0.4.6

## 更新内容

- 限速配置恢复可靠：新建自定义 Profile 不再被自动跳回已有配置，保存新配置后保持选中；此前在特定时序下保存会把改动误写入原有配置。
- 构造请求与集合请求现在发送到当前激活的工作区；此前固定发送到 default 工作区，切换工作区后请求会落错位置。
- 更新安装失败时在更新对话框与设置页给出明确错误提示，可直接重试；此前失败只表现为按钮恢复原状，没有任何说明。
- 中文界面下 HAR 导入的错误提示已本地化，并标明出错的具体条目；批量保存响应时如有失败会显示失败数量，不再只报成功数。
- 被拒绝的 WebSocket 升级在检视器中如实显示上游返回的响应内容与类型；此前始终显示空响应体，且被误标为 websocket。
- 改善证书排障：macOS/Linux 信任检查失败原因现在写入日志（与 Windows 一致），客户端时钟略慢时根证书不再被判为未生效、导致 HTTPS 抓包全失败。
- 多网卡机器上用 ADB 快捷菜单设置手机代理时，优先选择手机可达的局域网地址（192.168/10.x），不再固定取第一个网卡地址。
- 规则导入现在真正区分「文件版本不支持」与「文件无效」并给出对应提示。

## What's new

- Throttling profiles are reliable again: creating a New Custom profile no longer snaps back to an existing one, and the freshly saved profile stays selected. Previously a save in a certain timing could overwrite an existing profile's data by mistake.
- Composed and collection requests now go to the currently active workspace. They were hardcoded to the default workspace, so requests landed in the wrong place after switching workspaces.
- A failed update install now shows a clear error in the update dialog and the settings page, with an immediate retry; previously the failure only silently reset the button.
- HAR import errors are localized in the Chinese UI and name the offending entry, and batch-saving responses now reports how many failed instead of only the successes.
- Refused WebSocket upgrades now show the upstream's actual response body and type in the inspector; previously the body was always empty and mislabeled as websocket.
- Certificate troubleshooting is easier: trust-check failures on macOS/Linux now leave a log trail (matching Windows), and clients with slightly slow clocks no longer see the root CA as not-yet-valid, which used to fail all HTTPS captures.
- The ADB quick menu on multi-adapter machines now prefers a phone-reachable LAN address (192.168/10.x) instead of blindly using the first adapter.
- Rules import now genuinely distinguishes an unsupported file version from an invalid file, with the matching guidance for each.
