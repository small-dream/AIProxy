# AIProxy v0.2.5

## 更新内容

- 断点编辑更安全：待处理断点在超时/断开后切换时，编辑草稿会随请求一起重置，不再把上一个请求的 Header、Body 或状态码发给下一个请求，避免跨主机凭证泄漏和请求体被覆盖。
- 脚本与编码：脚本直接赋值 `bodyBase64` 现在会真正生效；GBK、Latin-1 等非 UTF-8 响应在 Inspector 中按原始字节以 base64 展示，HAR 导出可完整还原，不再出现整段 U+FFFD 乱码。
- HTTPS 调试更完整：直接访问 IP 地址（或客户端不发送 SNI）时也能正常解密，证书使用 IP SAN，不再握手失败。
- Agent / MCP：SSE、NDJSON 和带 BOM 的 JSON 响应中的密钥也会被脱敏；打开 AIProxy 完成数据库迁移后，MCP 客户端无需重启即可恢复读取；Agent 临时规则命中后，规则轨迹不再整批丢失。
- 抓包稳定性：客户端停滞的请求体会在超时后返回 408 并释放连接；逐字节慢速发送请求头不再长期占用连接；异常的 WebSocket 分块响应不会再无限占用内存。
- 规则与列表：优先级为负数或超出范围时不再导致整类规则消失；批量删除规则后列表立即刷新；HAR 导入超过 100 条时不再残留打不开的会话；更新安装失败后可直接重试。
- Linux：关闭系统代理后会清空原本为空的协议槽位，不再把 http/https 残留指向已停止的 AIProxy 端口。

## What's new

- Safer breakpoint editing: when a pending hit is released or times out and another one becomes active, the draft editors reset with it instead of sending the previous request's headers, body or status code to the next request — no more cross-host credential leaks or overwritten bodies.
- Scripts and encoding: assigning `bodyBase64` directly in a script now takes effect; non-UTF-8 responses (GBK, Latin-1, …) are shown as base64 from their original bytes in the Inspector and export exactly through HAR instead of becoming a wall of U+FFFD characters.
- More complete HTTPS debugging: direct IP targets (and clients that do not send SNI) can be decrypted, with IP SANs on the generated certificate instead of a failed handshake.
- Agent / MCP: secrets inside SSE, NDJSON and BOM-prefixed JSON responses are redacted too; after AIProxy runs the database migration, the MCP client recovers without a restart; rule traces from agent-only rules are no longer lost as a batch.
- Capture stability: a stalled request body is answered with 408 and releases the connection; byte-by-byte slow request headers no longer pin a connection; malformed chunked WebSocket responses can no longer consume unbounded memory.
- Rules and lists: negative or out-of-range priorities no longer make a whole rule category disappear; batch-deleting rules refreshes the list immediately; importing more than 100 HAR sessions no longer leaves unopenable rows; a failed update install can be retried directly.
- Linux: disabling the system proxy now clears protocol slots that were originally empty, so http/https no longer keep pointing at a stopped AIProxy port.
