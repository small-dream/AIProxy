# AIProxy v0.2.3

## 更新内容

- 修复 WebSocket 抓包在协商压缩（permessage-deflate）后“刚连上就断开”的问题：代理不再声明自己不支持的扩展，浏览器与支持压缩的服务端之间也能正常收发与记录。
- 修正弱网「丢包率」单位：此前填 1% 会让命中的请求全部被丢弃，Fast 4G / Slow 3G / Lossy Wi-Fi 预设的丢包强度也被放大 100 倍；现在按界面显示的百分比生效。
- 修复开机后没有自动接管系统代理的问题：工作区已开启系统代理时，冷启动会可靠地重新接管；Linux 下系统代理应用失败会自动回滚到原设置，不再让整机流量停在半配置状态。
- 规则与断点更可靠：脚本只修改 Header 时不再破坏 GBK / Latin-1 等非 UTF-8 页面内容；断点编辑响应头会保留多个 Set-Cookie；gzip / br 压缩的 JSON 响应也能用「Body Fields」改写，且改写后保持字段顺序，签名类接口不再因字段重排而校验失败。
- WebSocket 升级失败时立即返回 502（此前上游返回非法 101 会等待约 10 秒并把上游帧写进错误页）；MCP 工具收到超大 `since` 时长时返回参数错误，而不是让工具调用崩溃。
- 会话数据一致性：同一会话的详情记录强制唯一（修复搜索结果分页可能漏掉会话），Body 写入改为原子替换（读取不会再看到半截内容）；首次启动会自动清理历史版本可能产生的重复详情记录，无需手动操作。删除其他所有会话时，后端失败也不再丢失本地导入的会话。

## What's new

- WebSocket capture no longer drops the connection right after the handshake when compression (permessage-deflate) is negotiated: the proxy stops advertising extensions it cannot decode, so browsers and compression-capable servers work normally.
- Fixed the throttle packet-loss unit: typing 1% used to drop every matched request, and the Fast 4G / Slow 3G / Lossy Wi-Fi presets were 100x stronger than labelled. The value now behaves as the percentage shown in the UI.
- Fixed the system proxy not being re-applied on launch: a workspace that had it enabled now reliably reclaims it after a cold start, and a failed apply on Linux rolls back to the previous settings instead of leaving traffic half-configured.
- More reliable rules and breakpoints: header-only scripts no longer corrupt non-UTF-8 (GBK / Latin-1) bodies, editing response headers keeps every Set-Cookie value, and "Body Fields" rewrites now work on gzip / br JSON while preserving key order so signed payloads still verify.
- Failed WebSocket upgrades now answer 502 immediately (a malformed 101 used to stall for about 10 seconds and splice upstream frames into the error page), and MCP tools return a validation error for an out-of-range `since` window instead of crashing the tool call.
- Session data is consistent: details are now strictly one row per session (fixing search results pages that could hide sessions) and body files are written atomically (no more partial reads). Duplicate detail rows left by older versions are cleaned up automatically on first launch, and deleting all other sessions no longer loses locally imported ones when the backend fails.
