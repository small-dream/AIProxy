# AIProxy v0.1.24

## 更新内容

- 加固 Android 代理设置的安全性：通过 adb 配置代理时对主机名做严格白名单校验，防止设备端命令注入风险。
- 强制重新生成根证书前会先撤销旧根证书的系统信任，避免轮换后旧证书仍被系统信任。
- 修复部分脚本规则（`export` 与 `function` 之间带换行或多余空格）能通过校验却永不触发的问题，这些写法现在可以正常生效。
- 修复 HEAD 与 304 响应丢失上游 Content-Length 的问题，下载大小显示与缓存校验更准确。
- 修复 WebSocket 上游 TLS 名称解析失败时静默回退到 127.0.0.1 的问题，现在会明确报错而非校验错误的证书。
- 阻止保存不可能生效的 Rewrite 规则组合（如响应阶段配置 Query/Redirect 动作），并给出明确的内联提示。
- 批量删除会话的完成提示改为如实描述“已从当前容器移除”，避免误解为永久删除。

## What's new

- Hardened Android proxy setup: the host used for `adb` is now strictly validated to prevent device-side command injection.
- Forcing root CA regeneration now revokes system trust for the old certificate first, so a rotated CA no longer stays trusted.
- Fixed script rules that passed validation but never fired when `export`/`function` were separated by newlines or extra whitespace.
- Fixed HEAD and 304 responses dropping the upstream Content-Length, making download-size metadata and cache validation more accurate.
- Fixed WebSocket upstreams silently falling back to 127.0.0.1 when the TLS server name could not be parsed; the upgrade now fails with a clear error.
- Blocked saving impossible Rewrite rule combinations (e.g. Query/Redirect actions at the response stage) with a clear inline warning.
- Batch-removing sessions now honestly reports "removed from the current container" instead of implying permanent deletion.
