# 证书安装与抓包排障指南

AIProxy 通过本地根证书解密 HTTPS 流量。本文说明三平台(macOS / Windows / Linux)的证书安装、移动端/模拟器抓包,以及"装好了却抓不到"的常见原因与解决办法。

> 首次使用建议直接走应用内的**设置向导**(首次启动自动弹出;之后可在「会话」页顶部的设置清单点「打开设置向导」)。它能引导你完成:生成根证书 → 安装并信任 → 启动代理 → 开启系统代理 → 抓到第一条 HTTPS 流量。

## 目标状态:`captureReady`

只有满足以下全部条件,才算"能抓到 HTTPS 流量",设置清单才会消失:

1. 根证书已生成;
2. 根证书在本机**已信任**;
3. 代理**正在运行**;
4. **SSL 解密已开启**(否则代理只会转发 HTTPS 而不解密,无法抓到明文内容);
5. 流量已路由到 AIProxy(系统代理开启,或你显式选择手动配置代理)。

证书已信任 ≠ 可用。务必确认 SSL 解密开启 + 代理运行 + 流量路由这几步。

## 各平台安装与信任

### macOS
1. 在「证书」页点「安装证书」,或双击证书文件(`aiproxy-root-ca.cer`)。
2. 在「钥匙串访问」中把证书加入 **System** 钥匙串(不是 login)。
3. 双击该证书 → 展开「信任」→「使用此证书时」设为「始终信任」,关闭窗口。
4. 输入**管理员密码**确认。
5. 重启浏览器使信任生效。

### Windows
1. 点「安装证书」→ 选择「本地计算机」。
2. 放入「**受信任的根证书颁发机构**」(Trusted Root Certification Authorities)存储。
3. 完成向导,重启浏览器。

### Linux
1. 把证书复制到系统 CA 目录并更新:
   ```bash
   sudo cp aiproxy-root-ca.crt /usr/local/share/ca-certificates/aiproxy-root-ca.crt
   sudo update-ca-certificates
   ```
2. 不同发行版目录可能不同(Fedora/RHEL 用 `/etc/pki/ca-trust/source/anchors/` + `sudo update-ca-trust`)。
3. **系统代理自动设置仅支持 GNOME 与 KDE**;其他桌面环境请手动在浏览器/系统里设置 HTTP/HTTPS 代理指向 AIProxy。

## 常见失败对照表

### <a id="port-in-use"></a>代理端口被占用
- **症状**:启动代理失败,提示端口已被占用(`PORT_IN_USE` / "address already in use")。
- **原因**:另一个进程(常是上次未退出的 AIProxy,或其他抓包工具)占用了同一端口。
- **解决**:关闭占用端口的进程;或在代理设置里更换端口(默认 8888),再重试。

### <a id="cert-not-found"></a>证书未找到
- **症状**:安装/诊断时报「No certificate found」。
- **原因**:尚未生成根证书。
- **解决**:先在「证书」页或设置向导里**生成根证书**,再安装。

### <a id="proxy-not-running"></a>代理未运行
- **症状**:开启系统代理或配置移动端时报「Proxy not running」。
- **原因**:代理未启动(通常应用启动时会自动启动,但端口冲突等原因可能导致自启失败)。
- **解决**:从状态栏启动代理,确认端口可用后再开启系统代理/配置设备。

### <a id="permission-denied"></a>权限被拒绝
- **症状**:macOS 钥匙串/Windows 安装/Linux `sudo` 提示权限失败。
- **原因**:未授予管理员权限或钥匙串访问被拒。
- **解决**:重新执行并输入管理员密码 / 授权钥匙串;Linux 确认用了 `sudo`。

### <a id="installer-failed"></a>系统安装器无法打开
- **症状**:点「安装证书」后系统安装器未弹出或报错。
- **原因**:系统证书安装器关联异常。
- **解决**:在「证书」页手动定位证书文件并双击安装;或按上文各平台步骤手动安装。

### <a id="generate-failed"></a>生成根证书失败
- **症状**:生成报错(`rcgen` / 写盘失败)。
- **解决**:重试;若持续失败,查看开发日志 `logs/dev/aiproxy-desktop-dev.log` 排查写盘权限或磁盘空间。

### <a id="troubleshooting"></a>装好了却抓不到流量
若 `captureReady` 已达成,但「会话」页没有流量,逐项排查:

1. **浏览器没走代理**:确认系统代理已开启;或手动把浏览器指向 `127.0.0.1:8888`(或你配置的端口)。
2. **证书未生效**:回到「证书」页确认信任状态为已信任;必要时重新信任并重启浏览器。
3. **目标应用证书锁定(pinning)**:钉钉、银行类 App 常对证书做 pinning,会拒绝代理。先用普通浏览器验证链路,再处理 pinning 应用。

## 移动端 / 模拟器抓包

进入「证书」页的「移动端」标签。移动端有 **preflight 前置检查**:必须先「生成根证书 + 代理运行 + 本机局域网 IP 可达」,二维码/ADB/hdc/Simulator 面板才会解锁。

- **Android 真机(USB)**:开启 USB 调试,连接后用「Android 快捷操作」一键推送证书并设置系统代理(需 `adb` 在 PATH 或 `ANDROID_HOME` 已设)。注意多数 Android 设备仍需在系统证书管理里手动确认安装。
- **Android 模拟器**:同样通过 ADB,模拟器通常已带 root,证书可装为系统证书。
- **HarmonyOS NEXT 真机(USB)**:在开发者选项中开启 HDC 调试,连接后用「鸿蒙快捷操作」通过 `hdc` 推送证书到设备 `/data/local/tmp/`(需 `hdc` 在 PATH 或 `HDC_PATH` 已设,或已安装 DevEco Studio)。推送不等于安装或信任,仍需手动进入「设置 → 安全与隐私 → 加密与凭据 → 从存储设备安装」完成安装;若系统文件选择器看不到该推送路径,请改用二维码/设备浏览器下载证书后安装。手动安装的是用户/VPN 与应用证书,不是系统根证书;只有已 root 或可写系统分区的测试设备才适合安装为系统证书。HarmonyOS NEXT 无官方 hdc 全局 HTTP 代理命令,代理需在设备 Wi-Fi 设置里手动配置指向电脑 IP:端口。同一 Wi-Fi 网络是前提。
- **HarmonyOS NEXT 模拟器**:可通过 `hdc list targets -v` 识别并使用同一个 hdc 推送动作,但不需要“同一 Wi-Fi”。请在模拟器系统网络设置中手动配置代理,主机填当前电脑可被模拟器访问的 IP,端口填 AIProxy 代理端口。证书安装同样需要在模拟器系统设置中手动确认;如果看不到 hdc 推送文件,用模拟器浏览器打开证书下载链接安装。
- **iOS 模拟器**(仅 macOS):用「iOS 快捷操作」通过 `xcrun simctl keychain` 安装;安装后仍需在模拟器「设置 → 通用 → 关于本机 → 证书信任设置」手动开启完全信任。
- **iOS 真机**:不支持自动安装。用「证书下载二维码」在手机 Safari 打开下载,按系统引导安装描述文件并在「证书信任设置」启用;代理在手机 Wi-Fi 设置里手动配置指向电脑 IP:端口。同一 Wi-Fi 网络是前提。

## 诊断

「证书」页提供「运行诊断」(基于 `diagnose_certificate_setup` 命令),会汇总:证书是否存在/可读/已信任、`adb` 是否可用、`hdc` 是否可用、iOS 模拟器工具链是否就绪(仅 macOS),并给出每项结论与提示,帮助快速定位环境问题。

## FAQ

- **根证书安全吗?** 根证书在本机生成,私钥不出本机。不用时可在「证书」页移除并撤销信任。
- **换电脑/重装后要重新装证书吗?** 是。根证书与机器绑定,新机器需重新生成与信任。
- **信任后浏览器仍警告?** 彻底退出并重启浏览器;部分浏览器(Firefox)有独立证书库,需单独导入。
