# 断点使用指南

断点让你在请求发出前或响应返回前**暂停**流量，临时检查、修改请求或响应的字段，再决定放行、丢弃还是用模拟响应替换。它适合定位问题、手工改包验证、临时模拟。

## 功能定位

断点是「人肉介入」工具：命中后会**阻塞**该请求，等待你在拦截面板里操作。这和 [改写](./rewrite-rules.md) / [脚本](./script-rules.md) 的「自动改包」不同 —— 那些是规则自动执行，断点需要你手动处理每一次命中。

> 断点不会一直挂着：待处理的命中会在 **5 分钟后自动按原样放行**，拦截面板中的倒计时标签会显示剩余时间。调试完记得删除或禁用断点规则。

## 入口位置

1. 在左侧导航栏点击 **规则**
2. 点击顶部 **断点** 标签页

断点页使用与其他规则一致的内联工作台：左侧是规则搜索、规则列表和创建入口，右侧直接编辑选中规则。左侧创建区提供：

- **新建断点规则**：在列表末尾追加一条空白草稿，并在右侧编辑匹配条件
- **拦截所有请求**：立即添加一条已启用的全量规则，对每个请求的请求阶段生效
- **拦截所有响应**：立即添加一条已启用的全量规则，对每个请求的响应阶段生效

这类全量规则已存在时对应按钮会置灰——想恢复不拦截，在规则列表中禁用或删除该规则即可。规则列表为空时，创建入口会直接显示在空状态中。

需要精细控制时，点 **新建断点规则**，在右侧的身份行确认启用状态，再填写 URL 模式、匹配方式、HTTP 方法与匹配阶段，最后点击固定页脚中的 **保存**。

## 断点规则字段

断点规则的字段比其他规则更精简，**没有规则名称，也没有优先级**——命中即触发，按「首个命中」处理：

| 字段 | 说明 | 默认 |
|---|---|---|
| 启用 | 控制是否生效 | 开启 |
| URL 模式 | URL 匹配模式；必填（填 `*` 表示匹配全部——快捷按钮创建的就是这种规则） | — |
| 匹配方式 | URL 模式的匹配方式 | `Contains`（子串） |
| HTTP 方法 | 只匹配指定方法，留空表示全部 | 空（全部方法） |
| 匹配阶段 | 命中阶段：请求阶段或响应阶段 | 请求阶段 |

匹配方式可选 `Contains`（子串，默认）/ `Wildcard`（通配符）/ `Exact`（精确）/ `Regex`（正则），含义与 [改写的匹配方式](./rewrite-rules.md#匹配条件) 一致。

### Agent 自动化边界

断点是全局资源，不受 workspace 隔离。首版 Agent 自动化工具不能创建、更新、删除、启停断点，也不能远程处理命中的请求；相关计划返回 `FEATURE_NOT_AVAILABLE`。`manageGlobalAutomation` 只是后续能力的预留权限，当前不会开放断点写入。

Agent 可以分析会话中的断点命中与放行记录，但不能替你放行、丢弃、修改消息头 / 消息体或发送模拟响应。断点命中后仍需由你在拦截面板处理，否则会在 5 分钟后按原样放行。

## 命中后的拦截面板

请求或响应命中断点后，右侧会滑出**拦截面板**，并在导航栏规则图标上显示待处理断点数量徽章（点击可跳到规则页）。面板里你可以：

- **放行**：不做任何修改，继续走管线
- **丢弃**：终止该请求 / 响应，给客户端返回错误
- **模拟响应（仅请求阶段）**：用一个自定义响应直接替换，跳过上游

面板支持在多个待处理断点之间用上 / 下一个按钮切换，并显示「第 N / 总数」。

### 可编辑的字段

**请求阶段**可以修改：

- 查询参数（增删改）
- 请求头（增删改）
- 请求体（表单 / JSON / 原始内容模式，JSON 可一键格式化）

**响应阶段**可以修改：

- 状态码（100–599）
- 响应头
- 响应体

编辑消息体后，AIProxy 会自动移除 `content-encoding`、`content-md5`、`digest`、`etag` 等会与新消息体不一致的响应头，避免客户端校验失败。

**放行** 和 **模拟响应** 会校验 JSON 消息体：如果你编辑过的消息体（或模拟消息体）不再是合法 JSON，操作会被「Invalid JSON」提示阻止，修正后才能继续。**丢弃** 永远不会被阻止；未改动过或非 JSON 的消息体不做校验直接通过。

## 断点在管线中的位置

断点位于规则链路靠后的位置，因此能拿到前面规则改写后的结果：

```text
请求：Rewrite -> Map -> Script(onRequest) -> Breakpoint -> Throttle -> Upstream
响应：Upstream/Local Response -> Response Rewrite -> Script(onResponse) -> Breakpoint -> Throttle -> Client
```

## 模拟响应

在请求阶段点 **模拟响应** 进入模拟模式，可配置：

- 状态码（默认 200）
- 响应头（默认带 `content-type: application/json`）
- 响应体（默认一段示例 JSON）

确认后该请求直接返回这份模拟响应，不再访问上游。适合临时验证客户端对某种返回的处理。

## 典型用途

- **定位偶发问题**：对某个接口下请求断点，命中后检查真实消息头 / 消息体
- **手工改包**：临时改一个字段看后端反应，不用写改写规则
- **临时模拟**：用模拟响应快速返回一个假响应
- **验证客户端容错**：在响应阶段把状态码改成 500，看前端是否正确降级

## 断点规则管理

- 断点规则包含在规则页的[导入 / 导出](./rewrite-rules.md#规则导入--导出)文件中；导入的断点规则会追加到列表末尾、以禁用状态带新 id 落地。
- 列表顺序就是匹配顺序：命中第一条规则后立即触发断点。可拖拽行首把手，或使用 `Alt + ↑` / `Alt + ↓`（macOS 为 `⌥`）重排当前规则。
- 搜索只过滤可见规则；在搜索结果中重排时，隐藏规则保持原位置。
- 行首复选框可多选规则，随后批量启用、禁用或删除；单条删除和批量删除都会先确认。
- 草稿有未保存修改时，切换规则、切换标签页或离开页面都会先确认。`Ctrl/Cmd + S` 可保存当前草稿。
- 新建、复制和导入的规则都追加到列表末尾，不会抢占已有规则的位置。

## 常见问题

### Q: 命中后请求一直挂着没响应？

断点需要你处理：在拦截面板选放行 / 丢弃 / 模拟放行，或者等 5 分钟倒计时归零后自动按原样放行。如果面板被关掉，导航栏规则图标上的徽章会提示还有待处理断点。

### Q: 断点和改写 / 脚本有什么区别？

改写和脚本是**自动**改包，命中后静默执行；断点是**手动**介入，每次命中都要你操作。断点适合一次性调试，反复出现的改写建议沉淀成改写或脚本规则。

### Q: 为什么断点规则没有优先级？

断点按「首个命中」触发，多条规则只要有一条匹配就暂停，不需要优先级排序。

### Q: 调试完怎么清理？

在断点列表里禁用或删除对应规则，并处理掉残留的待处理断点，避免后续请求被一直挂起。
