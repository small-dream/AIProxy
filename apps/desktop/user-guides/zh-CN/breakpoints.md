# 断点（Breakpoint）使用指南

断点让你在请求发出前或响应返回前**暂停**流量，临时检查、修改请求或响应的字段，再决定放行、丢弃还是用 Mock 响应替换。它适合定位问题、手工改包验证、临时 Mock。

## 功能定位

断点是「人肉介入」工具：命中后会**阻塞**该请求，等待你在拦截面板里操作。这和 [Rewrite](./rewrite-rules.md) / [脚本](./script-rules.md) 的「自动改包」不同 —— 那些是规则自动执行，断点需要你手动处理每一次命中。

> 断点不会一直挂着：待处理的命中会在 **5 分钟后自动按原样放行**，拦截面板中的倒计时标签会显示剩余时间。调试完记得删除或禁用断点规则。

## 入口位置

1. 在左侧导航栏点击 **Rules**
2. 点击顶部 **断点（Breakpoint）** 标签页

页面顶部的「快捷断点」卡片提供两个一次性按钮：

- **拦截所有请求**：添加一条已启用的全量规则，对每个请求的请求阶段生效
- **拦截所有响应**：添加一条已启用的全量规则，对每个请求的响应阶段生效

这类全量规则已存在时按钮会置灰——想恢复不拦截，在下方列表中禁用或删除该规则即可。

需要精细控制时，点 **添加规则** 创建一条带匹配条件的断点规则。

## 断点规则字段

断点规则的字段比其他规则更精简，**没有规则名称，也没有优先级**——命中即触发，按「首个命中」处理：

| 字段 | 说明 | 默认 |
|---|---|---|
| 启用 | 控制是否生效 | 开启 |
| URL Pattern | URL 匹配模式；必填（填 `*` 表示匹配全部——快捷按钮创建的就是这种规则） | — |
| Match Type | URL Pattern 的匹配方式 | `Contains`（子串） |
| HTTP Methods | 只匹配指定方法，留空表示全部 | 空（全部方法） |
| Match Stage | 命中阶段：请求阶段 或 响应阶段 | 请求阶段 |

Match Type 可选 `Contains`（子串，默认）/ `Wildcard`（通配符）/ `Exact`（精确）/ `Regex`（正则），含义与 [Rewrite 的 Match Type](./rewrite-rules.md#匹配条件) 一致。

## 命中后的拦截面板

请求或响应命中断点后，右侧会滑出**拦截面板**，并在导航栏 Rules 图标上显示待处理断点数量徽章（点击可跳到规则页）。面板里你可以：

- **Forward（放行）**：不做任何修改，继续走管线
- **Drop（丢弃）**：终止该请求 / 响应，给客户端返回错误
- **Mock Response（仅请求阶段）**：用一个自定义响应直接替换，跳过上游

面板支持在多个待处理断点之间用上 / 下一个按钮切换，并显示「第 N / 总数」。

### 可编辑的字段

**请求阶段**可以修改：

- Query 参数（增删改）
- 请求 Headers（增删改）
- 请求 Body（Form / JSON / Raw 模式，JSON 可一键格式化）

**响应阶段**可以修改：

- 状态码（100–599）
- 响应 Headers
- 响应 Body

编辑 Body 后，AIProxy 会自动移除 `content-encoding`、`content-md5`、`digest`、`etag` 等会与新 Body 不一致的响应头，避免客户端校验失败。

**Forward（放行）** 和 **Mock Response** 会校验 JSON Body：如果你编辑过的 Body（或 Mock Body）不再是合法 JSON，操作会被「Invalid JSON」提示阻止，修正后才能继续。**Drop（丢弃）** 永远不会被阻止；未改动过或非 JSON 的 Body 不做校验直接通过。

## 断点在管线中的位置

断点位于规则链路靠后的位置，因此能拿到前面规则改写后的结果：

```text
请求：Rewrite -> Map -> Script(onRequest) -> Breakpoint -> Throttle -> Upstream
响应：Upstream/Local Response -> Response Rewrite -> Script(onResponse) -> Breakpoint -> Throttle -> Client
```

## Mock 响应

在请求阶段点 **Mock Response** 进入 Mock 模式，可配置：

- 状态码（默认 200）
- 响应 Headers（默认带 `content-type: application/json`）
- 响应 Body（默认一段示例 JSON）

确认后该请求直接返回这份 Mock 响应，不再访问上游。适合临时验证客户端对某种返回的处理。

## 典型用途

- **定位偶发问题**：对某个接口下请求断点，命中后检查真实 Headers / Body
- **手工改包**：临时改一个字段看后端反应，不用写 Rewrite 规则
- **临时 Mock**：用 Mock Response 快速返回一个假响应
- **验证客户端容错**：在响应阶段把状态码改成 500，看前端是否正确降级

## 断点规则管理

- 断点规则包含在 Rules 页的[导入 / 导出](./rewrite-rules.md#规则导入--导出)文件中；导入的断点规则会追加到列表末尾、以禁用状态带新 id 落地。
- 草稿有未保存修改时关闭「添加规则」对话框或切换标签页都会先确认；删除规则也会先确认。

## 常见问题

### Q: 命中后请求一直挂着没响应？

断点需要你处理：在拦截面板选 Forward / Drop / Mock 放行，或者等 5 分钟倒计时归零后自动按原样放行。如果面板被关掉，导航栏 Rules 图标上的徽章会提示还有待处理断点。

### Q: 断点和 Rewrite / 脚本有什么区别？

Rewrite 和脚本是**自动**改包，命中后静默执行；断点是**手动**介入，每次命中都要你操作。断点适合一次性调试，反复出现的改写建议沉淀成 Rewrite 或脚本规则。

### Q: 为什么断点规则没有优先级？

断点按「首个命中」触发，多条规则只要有一条匹配就暂停，不需要优先级排序。

### Q: 调试完怎么清理？

在断点列表里禁用或删除对应规则，并处理掉残留的待处理断点，避免后续请求被一直挂起。
