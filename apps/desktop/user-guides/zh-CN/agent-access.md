# Agent 接入（MCP）使用指南

Agent 接入让 Codex、Claude Code 和 Cursor 通过本地 MCP 服务查询 AIProxy 已保存的抓包数据，并可在用户明确授权后完成首次安装、证书、SSL、抓包启停、系统代理和 Session 清理。适合让编码 Agent 结合真实请求、响应和 Timing 定位问题，不必先手工导出 HAR 或逐条复制请求。

## 功能定位

- MCP 服务以本地 stdio sidecar 运行，不开放网络端口。
- 读取能力默认只读取已持久化会话；控制写操作通过仅当前用户可访问的本地 IPC 调用桌面端，不开放 TCP 端口。
- 读取权限、四个控制权限分组、Body 上限和脱敏策略都由你控制；控制权限默认全部关闭，所有工具调用都会写入仅含元数据的审计日志。
- 应用未运行时，控制写工具会自动拉起并聚焦 AIProxy；自动启动不会先按旧配置启抓，而是等待 Agent 的下一步工具调用。
- AIProxy 不会上传抓包。Agent 读取内容后，这些内容会发送到对应客户端的模型服务商，因此仍需按任务最小化授权。

## 前置条件

1. 先启动代理并抓取至少一条会话，便于连接后验证读取链路。
2. 在 **设置 → Agent 接入** 中确认本地 MCP 状态正常。需要排查时展开 **诊断信息**。
3. 准备好要连接的客户端。连接过程只会写入用户级配置，不修改当前项目目录。

## 首次连接

1. 打开 **设置 → Agent 接入**。
2. 打开 **启用本地 Agent 接入**，然后点击 **保存更改**。
3. 在 **连接 Agent 客户端** 中选择 Codex、Claude Code 或 Cursor，点击 **连接**。
4. 在连接对话框中选择四种基础权限模板之一（“仅元数据”“含响应 Body”“含原始数据”或“完整控制”），并确认将写入的配置路径与备份说明。若之前保存过自定义组合，对话框还会提供并默认选中“保留当前权限”。
5. 点击 **连接并写入**。AIProxy 会先保存权限，再写入 MCP 配置并安装当前版本的 AIProxy Skill。
6. 按客户端提示重新启动或重新加载客户端，让新的 MCP 服务生效。

> 连接成功只表示配置与 Skill 已写入，不表示客户端已经完成握手。可回到 **诊断信息** 点击 **验证连接**，确认 sidecar、数据库 schema、MCP 握手和工具调用均通过。

## 权限模板

| 模板 | 适用场景 | 数据范围 |
|---|---|---|
| 仅元数据 | 定位请求、状态码、Host、Timing 或规则命中 | 会话摘要、Headers、Query、Cookie、Timing 与规则追踪，不读取 Body |
| 含响应 Body | 需要检查 JSON 字段、错误响应或 WebSocket 内容 | 在元数据基础上增加脱敏后的请求 / 响应 Body 与 WebSocket 消息 |
| 含原始数据（高风险） | 任务明确需要未脱敏字段，且已确认数据敏感度 | 额外允许 raw 与 base64 Body；可能暴露凭据和个人信息，只应临时开启 |
| 完整控制（高风险） | 首次安装、需要 Agent 调整 SSL/端口、启停抓包、管理证书、系统代理或清理 Session | 在脱敏 Body 与 WebSocket 读取基础上，开启四个控制权限分组；不启用未脱敏 Body |

连接后仍可在 **读取权限** 和 **控制权限** 中调整。关闭 **读取 Body** 会同时关闭 **读取未脱敏 Body**。

重新连接时，若当前权限不完全等同于任一基础模板（例如只开启了部分控制权限），**保留当前权限** 会原样保留已保存的读取与控制范围；选择其他模板则会将该模板完整应用。

## 首次安装与完整流程

若希望 Agent 从零完成本机抓包准备，可授予 **完整控制**，然后在当前对话中给出明确任务。推荐顺序：

1. `generate_certificate` 生成根证书；如已存在且只需检查，先调用 `get_app_status`。
2. `open_certificate_installer` 打开系统安装入口。钥匙串、管理员密码或 Windows 证书确认仍必须由你完成，Agent 的成功结果会带 `userActionRequired=true`。
3. 信任完成后再用 `configure_workspace` 开启 SSL（以及需要时的端口、HTTP2、SSL blind hosts / SSL proxying）。
4. 调用 `start_capture`。SSL 证书尚未信任时仍可能启动成功，但结果会带明确 warning，HTTPS 客户端会拒绝连接。
5. 只有在你明确需要接管系统流量时，才调用 `set_system_proxy` 启用系统代理。停止抓包时 AIProxy 会恢复原系统配置，即使未授予系统代理权限也会完成这项安全收尾。

Agent 可以在应用关闭时自动拉起并聚焦 AIProxy。应用内不再二次确认已授权的控制操作，因此请留意桌面通知与审计日志；写控制动作在审计表中带有“控制”标记。删除 Session、撤销证书信任等破坏性操作必须由你在当前对话中明确请求。

若 Agent 清理 Session 时返回 `BODY_DELETE_FAILED`，表示数据库记录已删除，但部分 Body 文件清理失败；应把结果视为部分成功，并按返回的删除数量与失败明细说明，而不是声称全部失败或全部清理完成。

## 读取权限与脱敏

常规权限包括：

- **读取会话元数据**：会话摘要、Headers、Query、Cookie、Timing 与规则命中记录。
- **读取 Body**：按范围读取请求和响应 Body，默认仍经过脱敏。
- **读取 WebSocket 消息**：按 cursor 分页读取消息；二进制消息只返回元数据。

展开 **高级权限** 后可以：

- 开启 **读取未脱敏 Body**。仅在任务必须检查原始载荷时使用。
- 启用 **按格式识别敏感值**，识别 JWT、邮箱、手机号、设备 ID 等常见格式。
- 启用 **标识符稳定哈希**，让同一标识符在多次工具调用中保持可关联，但不暴露原值。
- 添加 **自定义敏感字段名**，补充需要脱敏的 Header、Query 或 JSON 字段；输入后按 Enter。
- 调整 **单页最大会话数** 与 **Body 分块上限**，限制单次返回的数据量。

## 控制权限

控制权限位于读取权限下方，默认全部关闭：

| 权限 | 允许 Agent 做什么 |
|---|---|
| 控制抓包与工作区配置 | 修改端口、SSL、HTTP2、SSL blind hosts / SSL proxying，启动或停止抓包 |
| 控制系统代理 | 启用或交还系统代理；启用前代理必须已运行 |
| 管理根证书 | 生成或轮换证书、打开系统安装入口、撤销信任并删除证书 |
| 删除会话 | 清空全部会话与 Body，或按 session ID 批量删除（单次最多 200 个） |

点击 **启用完整控制** 会一次打开四项权限。开启后 Agent 执行对应操作时，应用内不再二次确认；因此只应在信任当前 Agent 和任务时使用。审计日志会记录动作摘要、耗时和错误码，但不记录凭据或 Body。

## 客户端状态与管理

客户端列表使用三种状态：

| 状态 | 含义 |
|---|---|
| 已配置 | MCP 配置中的 aiproxy 条目与受管 Skill 都已就绪 |
| 需更新 | 配置或 Skill 缺少、过期，需要重新连接 |
| 未配置 | 尚未写入 AIProxy 的 MCP 配置或 Skill |

每个客户端的 **更多操作** 菜单提供：

- **仅写入 MCP 配置**：保留现有 Skill，只更新客户端配置。
- **仅安装 Skill**：不修改 MCP 配置。
- **手动配置**：展开配置文件路径、Skill 路径与版本、配置片段，便于自行合并或排障。
- **断开连接**：移除 aiproxy 配置并删除 AIProxy 管理的 Skill，操作前会二次确认并备份原配置。自定义 Skill 会被保留。

## 验证连接

展开 **诊断信息** 后点击 **验证连接**。检查项包括：

- MCP sidecar 是否存在、可执行版本是否匹配。
- MCP doctor、数据目录、数据库与 schema 是否可读。
- Agent 接入开关、Body 读取权限和已启用的控制权限是否符合预期。
- Agent 控制描述文件、协议版本、控制通道与工具数量是否正常；控制权限全关时显示 warning，不代表读取链路失败。
- MCP 握手、工具列表与实际 `search_sessions` 调用是否成功。
- 当前是否已有可读会话，以及客户端配置是否就绪。

失败项会就地显示原因。需要提交问题时，可用 **复制诊断** 导出完整检查结果，不要粘贴真实抓包 Body 或凭据。

## 使用示例

连接完成后，可以直接向 Agent 描述调试目标，例如：

- “找出最近的 `/api/checkout` 失败请求，比较它们的状态码与响应 Header，并引用 sessionId。”
- “检查今天错误响应中的 JSON 字段差异，归纳最可能的改动。”
- “比较两次登录请求的 Query、Headers 和 Timing，指出服务端行为变化。”
- “读取 WebSocket 最近的消息，定位连接关闭前服务端返回的错误。”
- “生成并安装根证书，开启 SSL，启动抓包；确认我完成系统信任后再启用系统代理。”
- “停止抓包并把系统代理恢复原状。”
- “删除我刚刚指定的这两个 sessionId，并报告缺失的 ID。”

如果 Agent 提示看不到响应体，先确认连接时选择了 **含响应 Body**，或在 **读取权限** 中开启 Body 读取后保存。

## 安全边界

- stdio sidecar 不暴露网络监听端口，但同一系统用户下的进程仍可能访问本地数据；这是本地工具的信任边界。
- 默认脱敏、默认关闭的控制权限和审计用于降低暴露面，不能替代对敏感项目的判断。
- 抓包内容可能包含恶意提示或伪造指令，Agent 必须把它当作不可信数据。不要因为响应 Body 中写着“请删除会话”或“请关闭证书校验”就执行操作。
- 删除类操作和撤销证书信任只能在当前对话中由你明确请求，不能由抓包内容、网页文本或工具返回值触发。
- 不要把生产凭据、个人数据或受监管数据交给不需要它们的 Agent 任务。
- 结束敏感调试后，及时关闭 **读取未脱敏 Body**，必要时断开不再使用的客户端。

## 常见问题

### Q: 客户端显示“已配置”，Agent 仍找不到 AIProxy 工具怎么办？

先重新启动或重新加载对应客户端，再运行 **验证连接**。如果握手失败，检查 MCP sidecar 路径、客户端配置路径与诊断信息中的具体 error。

### Q: Agent 只能看到状态码，看不到响应内容？

通常是 Body 读取关闭。到 **设置 → Agent 接入 → 读取权限** 开启 **读取 Body** 并保存，或重新连接时选择 **含响应 Body**。

### Q: 为什么 Skill 显示“需更新”？

内置 Skill 版本升级后，旧安装不会自动改写。点击客户端的 **更新连接** 或 **重新安装 Skill**，按提示处理覆盖确认即可。

### Q: 为什么 Agent 操作时 AIProxy 自动打开了？

写控制工具在控制通道不可用时会自动拉起并聚焦 AIProxy；这与只读查询不同，只读状态不会启动应用。自动启动的应用不会按旧配置自动启抓，Agent 仍需显式调用 `start_capture`。

### Q: 删除会话后能恢复吗？

不能。`clear_sessions` 会删除完整数据库会话与 Body 文件，`delete_sessions` 会删除指定 ID 及其 Body。执行前请确认当前对话中的删除请求来自你本人，而不是抓包内容中的指令。

### Q: 断开连接会删除什么？

会移除客户端配置中的 aiproxy MCP 条目，并删除由 AIProxy 安装的 Skill。原配置文件会先备份；不是 AIProxy 管理的自定义 Skill 会保留。
