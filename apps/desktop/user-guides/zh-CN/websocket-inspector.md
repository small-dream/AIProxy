# WebSocket 消息检查与重放使用指南

## 功能简介

WebSocket 消息检查器允许你实时查看、搜索和重放 WebSocket 连接中的每一帧消息。支持 `ws://` 和 `wss://` 协议，适用于即时通讯、协作编辑、实时推送等场景的调试。

## 典型用途

- **实时监控**：查看 WebSocket 连接中所有上行和下行消息，逐帧检查内容
- **协议调试**：排查消息格式、时序问题，确认客户端和服务端的通信行为
- **消息重放**：编辑并重新发送已有消息，测试服务端对不同内容的响应
- **主动注入**：在活跃连接上发送自定义消息，模拟客户端或服务端行为

## 入口位置

1. 打开 AIProxy 并启动代理
2. 在左侧会话列表中找到 WebSocket 会话（带有 WebSocket 图标，协议显示为 `ws` 或 `wss`）
3. 点击该会话，右侧 Inspector 面板的 Response 区域会出现 **Messages** 标签页
4. 点击 **Messages** 标签进入消息检查器

## 消息列表

打开某个会话的 Messages 标签时，AIProxy 会从数据库加载**最早存储的 500 帧**，之后实时到达的帧会持续追加（内存中最多保留 10,000 帧）。因此特别长的会话可能只显示最早的那部分帧。

左侧消息列表展示已加载的帧，每行包含：

| 列 | 说明 |
|---|---|
| 时间 | 消息帧的捕获时间 |
| 类型标签 | 帧的操作码（text、binary、close、ping、pong） |
| 内容预览 | 文本帧显示前 60 个字符，二进制帧显示大小 |
| 大小 | 帧负载的字节数 |
| Truncated 标签 | 重组触及 20 MiB 捕获上限时显示（见下文） |
| ▶ 按钮 | Replay 按钮（活跃连接上任何带可读文本的帧都会显示——文本帧以及带原因说明的 close 帧） |

点击任意消息行，右侧会显示该帧的详细信息。

### 方向过滤

通过顶部标签页按方向筛选消息：

| 选项 | 说明 |
|---|---|
| All | 显示所有消息 |
| Sent（↑） | 仅显示客户端发送到服务端的消息 |
| Received（↓） | 仅显示服务端发送到客户端的消息 |

### 类型过滤

通过第二个标签页按操作码筛选：

| 选项 | 说明 |
|---|---|
| All | 显示所有类型 |
| Text | 文本帧（含 continuation 帧） |
| Binary | 二进制帧 |
| Control | 控制帧（close、ping、pong） |

### 搜索

在搜索框中输入关键词，实时过滤当前已加载的消息。搜索会同时匹配消息内容（`payloadText`）和操作码。注意它只覆盖上面描述的加载窗口，不会查询长会话的完整数据库历史。

### 超大消息

单条 WebSocket 消息由多个帧重组，上限为 **20 MiB**；超过后仅保留前 20 MiB。这类消息行会显示 **Truncated** 标签，详情面板会说明仅捕获了原始负载的前缀部分。

## 消息详情

选中一条消息后，右侧详情面板显示：

- **帧元信息卡片**：方向、操作码、FIN 标志、时间戳、负载大小
- **格式切换**：支持三种显示格式
  - **Text**：原始文本
  - **JSON**：自动检测并格式化 JSON（仅 JSON 内容可用）
  - **Hex**：十六进制转储视图
- **复制按钮**：复制当前格式下的消息内容到剪贴板

## 连接状态

消息面板右上角显示当前连接状态：

- 🟢 **活跃**：WebSocket 连接仍在运行，可以发送消息
- ⚪ **已关闭**：连接已断开，Compose 和 Replay 功能不可用

状态会实时更新，无需刷新页面。

## 消息重放（Replay）

在活跃连接上，你可以重放已有的文本消息：

1. 在消息列表中找到要重放的消息
2. 点击该消息行右侧的 **▶** 按钮
3. 底部编写面板自动展开，预填该消息的方向和内容
4. 按需修改内容
5. 点击 **发送** 按钮

重放的消息会通过代理注入到实际连接中，服务端会像收到正常消息一样处理。注入的消息同时会出现在消息列表中，标记为 `clientToServer` 或 `serverToClient`。

## 编写自定义消息（Compose）

除了重放已有消息，你还可以编写全新的消息发送到活跃连接：

1. 点击消息面板右上角的 **✉**（Compose）按钮
2. 底部编写面板展开
3. 选择消息方向：
   - **Send to Server**：模拟客户端发送消息到服务端
   - **Send to Client**：模拟服务端发送消息到客户端
4. 选择操作码：Text（默认）、Ping、Pong
5. 在文本框中输入消息内容
6. 点击 **发送** 按钮

注意事项：

- Compose 按钮仅在连接状态为"活跃"时可用
- 发送后消息会立即出现在消息列表中
- 发送失败时会显示错误提示

## 工作原理

1. AIProxy 代理拦截所有 HTTP/HTTPS 请求中的 WebSocket 升级（`Upgrade: websocket`）
2. 代理建立到上游的连接，完成握手后进入双向帧中继模式
3. 每一帧经过解析后，提取方向、操作码、负载内容等信息，存储到数据库并实时推送到前端
4. 活跃连接在代理层注册到全局 `WsConnectionRegistry`，前端通过查询注册表获取连接状态
5. 重放/注入的消息通过内部通道传入中继循环，作为正常帧转发到目标方向

这意味着：

- 代理不会修改 WebSocket 消息内容，只做透传和记录
- 二进制帧仅记录大小，不存储实际内容（节省存储空间）
- 注入的消息对服务端/客户端来说是透明的，与正常消息无异
- 如果连续 5 分钟没有收到任何帧，代理会关闭该连接；一帧传到一半停住则必须在 30 秒内传完，否则同样关闭。这些超时用于防止死连接长期占用资源。

## 适用协议

| 协议 | 说明 |
|---|---|
| `ws://` | 明文 WebSocket，代理通过 HTTP 升级拦截 |
| `wss://` | 加密 WebSocket，代理通过 HTTPS MITM 解密后拦截 |

前提条件：`wss://` 连接需要已安装并信任 AIProxy 的根 CA 证书。

## 常见问题

### Q: 为什么有些消息只显示大小，没有内容？

二进制帧（opcode: binary）的负载不会保存实际内容，仅记录字节数。如果需要查看二进制帧的完整内容，请考虑使用其他工具将二进制协议转换为文本格式。

### Q: Compose 按钮是灰色的无法点击？

Compose 和 Replay 功能仅在 WebSocket 连接处于"活跃"状态时可用。如果连接已关闭（状态指示器显示灰色），这些按钮会自动禁用。请刷新页面重新建立 WebSocket 连接后再试。

### Q: 重放的消息会出现在消息列表中吗？

会。所有注入的消息都会通过正常的捕获流程出现在消息列表中，你可以像查看其他消息一样查看它们的内容和元信息。

### Q: 可以修改重放消息的方向吗？

可以。在 Replay 打开的编写面板中，你可以切换方向为"Send to Server"或"Send to Client"。

### Q: 搜索框只能搜索当前显示的消息吗？

搜索框对已加载的窗口做客户端过滤：最早的 500 帧，加上面板打开期间实时收到的帧。它不会查询该窗口之外的完整数据库历史。

### Q: 长连接为什么被断开了？

代理通过空闲超时防止死连接长期占用：连续 5 分钟没有收到任何帧就关闭连接；一帧传到一半停住必须在 30 秒内传完。任意一方发送 ping 保活帧即可避免空闲断开。

### Q: WebSocket 会话在会话列表中怎么识别？

WebSocket 会话在左侧会话树中带有 WebSocket 图标（水滴形），协议列显示 `ws` 或 `wss`，状态码为 `101`（Switching Protocols）。你也可以通过响应的 `responseMimeType: "websocket"` 来识别。
