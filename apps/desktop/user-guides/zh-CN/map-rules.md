# 映射规则（本地映射 / 远程映射）使用指南

映射规则让你把命中的请求**指向别处**：要么直接返回本地文件（本地映射），要么把请求转发到另一个上游地址（远程映射）。两者共用同一套字段，区别在于目标是「本地路径」还是「远程 URL」。

## 功能定位

- **本地映射**：命中后**直接返回本地文件内容**，跳过上游。适合模拟固定响应、用本地构建产物替换线上静态资源。
- **远程映射**：命中后**改写上游目标 URL**，继续走完整代理管线。适合一键切环境（生产 → 预发 / 模拟网关）。

> 远程映射和 [改写的重定向](./rewrite-rules.md) 不同：重定向是给客户端返回一个重定向响应（客户端再发起新请求）；远程映射是在代理内部悄悄换上游，客户端无感知，且原始抓包上下文保留。

## 入口位置

1. 在左侧导航栏点击 **规则**
2. 点击顶部 **映射** 标签页
3. 在映射内切换到 **本地映射** 或 **远程映射** 子标签（与 [DNS 映射](./dns-mapping.md) 并列）

## 共用字段

本地映射和远程映射共用同一组字段：

| 字段 | 说明 | 默认 |
|---|---|---|
| 规则名称 | 便于识别 | — |
| 启用 | 控制是否生效 | 开启 |
| 优先级 | 数字越大越优先；多条命中取最高。可在列表里拖拽行调整顺序并自动重排优先级 | `100` |
| 来源 URL 模式 | 要匹配的请求 URL 模式，按匹配方式解释 | — |
| 匹配方式 | 模式匹配方式：包含（默认）/ 通配符 / 精确 / 正则 | 包含 |
| 保留路径（Preserve 路径） | 是否保留原请求的 path | 开启 |
| 保留查询参数（Preserve 查询参数） | 是否保留原请求的查询参数 | 开启 |

默认 **包含** 方式下：空值或 `*` 匹配全部，否则请求 URL 需包含该子串——例如 `example.com/assets/` 会匹配该路径下的请求。其他方式：**通配符** 用 `*` 占位但两端锚定（不以 `*` 开头的模式必须从 URL 开头匹配，不以 `*` 结尾的模式要匹配到结尾）；**精确** 要求整个 URL 与模式完全相等；**正则** 编译为正则表达式（非法正则会静默地永不命中）。

多条规则命中时，按**优先级降序**取最高的一条。

### 管理映射规则

勾选行前复选框可批量 **启用 / 禁用 / 删除**；拖动行首把手可排序（优先级自动重排，列表顺序即优先顺序）。也可以在 [会话](./sessions.md) 里右键某条请求 → **本地映射此请求**，会基于该主机 + 路径预填一条新草稿。本地映射 / 远程映射规则包含在规则页的[导入 / 导出](./rewrite-rules.md#规则导入--导出)中。

### Agent 映射规则

映射列表可能包含两类 Agent 资源，需要区分：

- **旧版临时规则**：`create_agent_rule` 可创建同主机远程映射或本地模拟响应。它们只存在内存中，默认 600 秒、最长 3600 秒，应用重启后消失；规则行只读，可通过 **清除全部 Agent 规则** 或 `remove_agent_rules` 清理。
- **自动化实验资源**：首版只支持创建、更新和验证 **本地映射**，会带 `Agent · 临时` 或 `Agent · 常驻` 标记。临时资源只能新建，不能更新或删除已有资源；常驻资源会写入规则库，需在 **规则 → Agent 实验** 回滚，或由你点击 **转为我的规则** 后再编辑。

自动化本地映射的文件必须位于 **设置 → Agent 接入 → 本地映射批准根目录** 内，或引用同一计划托管的上传资产。最多批准 10 个根目录，且只能通过系统选择器添加；目录失效会保留并显示 warning。越界、文件不存在、不是普通文件或符号链接逃逸返回 `PATH_NOT_APPROVED`。

首版自动化 **不允许写远程映射**。即使开启“映射到其他主机”，`validate_automation_plan` / `apply_automation_plan` 对远程映射仍返回 `FEATURE_NOT_AVAILABLE`；跨主机站点来源白名单仅为后续版本预留，不能绕过此限制。旧 `create_agent_rule` 的同主机远程映射仍是旧临时规则能力，不属于自动化实验，也不能证明远程映射的持久化写入已经开放。

Agent 复制映射规则会生成普通持久化规则，但不会删除原 Agent 资源。实验结束后应明确回滚或清理，不要只依赖复制和到期时间。

## 本地映射：返回本地文件

**目标**字段填**本地文件或目录路径**（可用「选择文件 / 选择目录」按钮拾取）：

- 指向**文件**：命中后直接返回该文件内容
- 指向**目录**：根据请求 path 在该目录下定位文件（开启「保留路径」时按原 path 拼接）；目录根且无 path 时默认返回 `index.html`

返回的响应：

- 状态码固定 **200**
- `Content-Type` 按文件后缀自动推断（如 `.json` → `application/json`、`.js` → JavaScript、`.png` → image/png 等，无法识别时为 `application/octet-stream`）
- 消息体为文件原始内容

> 出于安全考虑，请求 path 中的 `.` / `..` 会被清理，防止越出目标目录读取任意文件。

### 命中后的管线行为

本地映射直接产生本地响应，因此：

- **跳过上游请求**
- 请求阶段的 [脚本](./script-rules.md) `onRequest` 不会执行
- 但响应阶段的改写 / 脚本 `onResponse` 仍会继续处理这份本地响应

## 远程映射：转发到另一个上游

**目标**字段填一个 **`http://` 或 `https://` 开头的基地址**（例如 `https://staging.example.com`）：

- 命中后，请求的主机 / 上游被替换为该目标
- 开启「保留路径 / 保留查询参数」时，原请求的 path 和查询参数会拼到新目标上。目标 URL 的 path 会作为 base path 使用，并自动合并斜杠：目标 `/gateway/` + 原路径 `/v1/users` 最终为 `/gateway/v1/users`。
- 请求**继续走完整代理管线**（[脚本](./script-rules.md) / [断点](./breakpoints.md) / [限速](./throttling.md) / 上游），不是给客户端返回重定向

例如来源 `api.example.com`、目标 `https://staging.example.com`，开启保留路径与查询参数后，`https://api.example.com/v1/users?id=1` 会被转发到 `https://staging.example.com/v1/users?id=1`，客户端完全无感知，且会话里仍保留原始 URL 上下文。

## 远程映射 vs 改写重定向

| 维度 | 远程映射 | 改写重定向 |
|---|---|---|
| 行为 | 代理内部换上游，继续走管线 | 给客户端返回 3xx 重定向响应 |
| 客户端感知 | 无感知，连接不中断 | 客户端会再发起新请求到目标 |
| 抓包上下文 | 保留原始 URL | 出现新的重定向请求 |
| 适用 | 切环境、切上游 | 强制客户端跳转 |

## 典型用途

### 本地映射

- 把某个 API 映射到本地一份固定 JSON 做模拟
- 用本地构建产物（`dist/`）替换线上 JS / CSS，调试前端改动而无需发布
- 把图片 / 字体等静态资源指到本地缓存

### 远程映射

- 一键把生产域名切到预发环境联调
- 把某接口切到模拟网关
- 临时把流量导到本机起的另一服务

## 常见问题

### Q: 本地映射设置了却没返回本地文件？

检查：

1. 规则是否启用
2. 在当前匹配方式下来源 URL 模式是否真的能命中该请求 URL
3. 目标路径是否存在、可读
4. 是否有更高优先级的规则先命中
5. 如果指向目录，确认请求 path 能在该目录下找到对应文件

### Q: 本地映射命中后脚本为什么不执行？

本地映射在请求阶段直接返回本地响应，所以 `onRequest` 被跳过；但响应阶段的 `onResponse` 仍会执行。

### Q: 远程映射和改写重定向该用哪个？

想「悄悄换上游、客户端无感」用远程映射；想「让客户端跳到新地址」用改写重定向。

### Q: 目录映射时访问根路径返回什么？

默认返回目录下的 `index.html`。请求 path 里的 `.` / `..` 会被清理，无法越出目标目录。
