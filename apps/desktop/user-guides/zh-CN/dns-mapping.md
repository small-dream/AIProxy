# DNS 映射 / Host Override 使用指南

## 功能简介

DNS 映射允许你将指定域名解析到自定义 IP 地址，无需修改系统 hosts 文件或应用代码。适用于多环境联调、灰度验证、后端服务切换等场景。

## 典型用途

- **多环境切换**：将 `api.example.com` 指向测试环境 IP，无需改代码或配置文件
- **灰度验证**：将域名指向灰度服务器，验证新版本行为
- **本地开发**：将远程域名指向 `127.0.0.1`，配合本地服务调试
- **故障排查**：临时将域名指向其他节点，定位网络问题

## 入口位置

1. 打开 AIProxy
2. 在左侧导航栏点击 **Rules**
3. 点击顶部 **Mapping** 标签页
4. 在 Mapping 内切换到 **DNS** 子标签（与 Map Local、Map Remote 并列）

## 创建 DNS 映射规则

1. 点击左侧面板的 **新建 DNS 映射** 按钮
2. 在右侧编辑器中填写以下字段：

| 字段 | 说明 | 示例 |
|---|---|---|
| 规则名称 | 为规则起一个便于识别的名字 | `测试环境 API` |
| 启用开关 | 控制规则是否生效 | 开启 |
| 优先级 | 数字越大优先级越高，多条规则匹配时取最高优先级。可在列表里拖拽行调整顺序 | `100` |
| 主机名模式 | 要匹配的主机名，按 Match Type 解释（详见下文） | `example.com` |
| Match Type | 模式匹配方式：Contains（默认）/ Wildcard / Exact / Regex | Contains |
| 目标 IP | 匹配成功后解析到的 IP 地址 | `192.168.1.100` |

3. 点击 **保存**，规则立即生效

## 主机名模式说明

默认 **Contains** 方式下，代理把请求的目标主机名与模式做「是否包含该字符串」的判断。

| 模式 | 匹配范围 |
|---|---|
| `example.com` | 匹配任何主机名中包含 `example.com` 的请求，例如 `example.com`、`api.example.com`、`www.example.com` |
| `api.` | 匹配所有包含 `api.` 的主机名，例如 `api.example.com` |
| `*` 或留空 | 匹配所有主机名（不建议在生产中使用） |

其他匹配方式：**Wildcard** 下 `*.example.com` 是真正的通配符——只覆盖子域，不含裸域 `example.com`；**Exact** 要求主机名完全相等；**Regex** 对主机名编译正则表达式。

匹配规则：

- Contains 方式下为**子串包含**：请直接写公共后缀（如 `example.com`）来覆盖一个域名及其子域
- 匹配**区分大小写**，按主机名原文比对；主机名通常为小写，建议模式也统一使用小写
- 多条规则命中时，按**优先级降序**取优先级最高的一条

## 目标 IP 格式

支持 IPv4 和 IPv6 地址：

- IPv4：`192.168.1.100`、`127.0.0.1`、`10.0.0.1`
- IPv6：`::1`、`2001:db8::1`

## 规则管理

### 启用 / 禁用

通过编辑器中的开关切换规则的启用状态。禁用后规则不会被匹配，但保留配置。

### 搜索

在左侧面板的搜索框中输入关键词，可按规则名称、主机名模式或目标 IP 过滤。

### 删除

选中规则后点击编辑器顶部的 **删除** 按钮。

### 优先级

当多条规则同时匹配一个域名时，优先级数字最大的规则生效。建议对不同用途的规则设置不同的优先级以避免冲突。勾选行前复选框可批量启用 / 禁用 / 删除，拖动行首把手可排序（优先级自动重排，列表顺序即优先顺序）。DNS 映射包含在 Rules 页的[导入 / 导出](./rewrite-rules.md#规则导入--导出)中。

## 工作原理

DNS 映射在代理层生效，不影响系统 DNS 设置：

1. 代理收到请求后，提取目标主机名
2. 按优先级查找匹配的已启用 DNS 映射规则
3. 如果命中，将实际连接目标替换为映射 IP，但保留原始 Host 头和 TLS SNI
4. 请求正常转发到映射 IP 所在的服务器

这意味着：

- 目标服务器收到的 `Host` 头仍然是原始域名（如 `api.example.com`），而不是 IP 地址
- HTTPS 连接的 TLS SNI 使用原始域名，不会触发证书校验错误
- 不影响系统 DNS 设置，关闭代理后映射自动失效

## 适用范围

DNS 映射对以下代理路径全部生效：

- HTTP 请求转发
- HTTPS MITM 解密
- HTTP WebSocket 升级
- HTTPS WebSocket 升级
- HTTPS 盲隧道（未解密的 HTTPS 流量）

**例外**：Compose（构造请求）页面发送的直接请求不应用 DNS 映射，保持原始请求语义。

## 数据持久化

DNS 映射规则持久化到本地 SQLite 数据库，应用重启后规则自动恢复，无需重新配置。

## 常见问题

### Q: 设置了映射但请求仍然连接到原来的 IP？

检查以下几点：

1. 规则是否已**启用**
2. 主机名模式是否正确匹配目标域名
3. 代理是否正在运行且系统代理已开启
4. 是否有更高优先级的规则先匹配了该域名

### Q: 设置映射后 HTTPS 网站报证书错误？

DNS 映射不改变 TLS SNI，正常情况下不会导致证书错误。如果出现此问题，请检查：

1. 目标 IP 对应的服务器是否配置了该域名的证书
2. 是否已正确安装并信任 AIProxy 的根证书

### Q: 可以同时配置多条 DNS 映射吗？

可以。多条规则按优先级排序，匹配时取优先级最高的第一条命中规则。建议为不同域名配置独立规则，避免使用过于宽泛的子串（例如直接写 `com` 会匹配大量无关主机名）。

### Q: 映射会影响其他应用吗？

DNS 映射仅在 AIProxy 代理生效范围内起作用。只有流量经过 AIProxy 代理的应用（即系统代理或手动代理指向 AIProxy 的设备）才会受到映射影响。关闭系统代理或停止 AIProxy 后，映射不再生效。
